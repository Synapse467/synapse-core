- [x] Bug found + fixed (serious): `pnpm dev` in `synapse-api` was **completely broken** — crashed on every single start. Root cause: `tsx`/esbuild does not emit `design:paramtypes` decorator metadata, which is how NestJS resolves this codebase's implicit, type-based constructor injection (used by every service). Verified directly (`Reflect.getMetadata('design:paramtypes', Jobs)` → `undefined` under tsx vs. a correct array under real `tsc`). This silently left every provider's injected dependencies `undefined`; it didn't surface immediately for most services, but `Jobs.onModuleInit` dereferences `this.db` unconditionally at boot. The README's documented workflow (`pnpm build && pnpm start`) uses the real compiler and was unaffected, which is why this went unnoticed. Fixed by switching the `dev` script to `tsc --watch` + `node --watch` (real compiler, zero new dependencies); removed the now-dead `tsx` devDependency. Also stopped `main.ts` from swallowing the real startup error behind a generic message.
